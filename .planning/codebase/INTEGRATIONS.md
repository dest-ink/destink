# External Integrations

**Analysis Date:** 2026-02-26

## APIs & External Services

**AI & Content Generation:**
- Anthropic Claude - Generates article drafts, analyzes voice samples, brainstorms topics
  - SDK/Client: `@anthropic-ai/sdk` 0.78.0
  - Auth: `ANTHROPIC_API_KEY` env var
  - Models used: claude-opus-4-6, claude-sonnet-4-6, claude-haiku-4-5-20251001
  - Implementation: `src/lib/ai/client.ts` (callClaude function)
  - Audit logging: `src/lib/ai/audit.ts` tracks usage to `ai_audit_log` table

**Research & Content Discovery:**
- Exa (Web Search API) - Discovers relevant web content for topics
  - SDK/Client: `exa-js` 2.5.0
  - Auth: `EXA_API_KEY` env var
  - Implementation: `src/lib/research/exa.ts`
  - Max 5 queries per run, 3 results per query, configurable excluded domains

- Reddit (Public JSON API) - Aggregates trending posts from configured subreddits
  - Auth: None required (public API)
  - Implementation: `src/lib/research/reddit.ts`
  - Max 5 subreddits, 10 posts per subreddit

- Substack (RSS/Atom Feeds) - Monitors RSS feeds from Substack publications
  - SDK/Client: `rss-parser` 3.13.0
  - Auth: None required (public RSS)
  - Implementation: `src/lib/research/substack-monitor.ts`
  - Max 10 feeds, 5 articles per feed

**Publishing:**
- Substack Notes API - Publishes notes to Substack (notes only, not articles)
  - SDK/Client: `substack-api` 2.2.1
  - Auth: Token stored encrypted in database
  - Implementation: `src/lib/publishing/substack.ts`
  - Credentials format: `{ publicationUrl: string, token: string }`
  - Limitation: Articles not supported; only notes via newNote() API

- LinkedIn ugcPosts API - Publishes text posts to LinkedIn
  - Auth: OAuth 2.0 access token + person URN (stored encrypted)
  - Implementation: `src/lib/publishing/linkedin.ts`
  - Credentials format: `{ accessToken: string, personUrn: string }`
  - Limitation: Articles not supported; max 3000 characters per post
  - OAuth callback: `http://localhost:3021/api/auth/linkedin/callback` (configured)

## Data Storage

**Databases:**
- PostgreSQL 12+ (primary)
  - Connection: `DATABASE_URL` env var
  - Client: Drizzle ORM with `pg` driver
  - Schema location: `src/db/schema.ts`
  - Migrations: `src/db/migrations/` (generated by drizzle-kit)
  - Pool config: Max 10 connections, dev-only global singleton to prevent hot-reload exhaustion

**File Storage:**
- Local filesystem only

  - Draft content stored in `drafts.*` columns (database)

**Caching:**
- None detected (all queries are fresh from database)

**Auth Provider:**
- Custom implementation (no third-party auth service)

- OAuth 2.0 (required for LinkedIn integration)

- Redirect URI: `http://localhost:3021/api/auth/linkedin/callback` (configured in .env.example)

## Data Flow

**Research Pipeline:**
1. `POST /api/research` triggers `runResearchForChannel()`
2. Parallel execution via `src/lib/research/orchestrator.ts`:
   - Exa search (web results)
   - Reddit API (subreddit posts)
   - Substack feed monitoring (RSS)
3. Deduplicated by URL, results stored in `researchRuns` table
4. Topics brainstormed via Claude (via `src/lib/research/brainstorm.ts`)

**Generation Pipeline:**
1. Research sources + voice profile + brainstormed topics fed to Claude
2. Draft generated via `src/lib/generation/generator.ts`
3. Draft stored in `drafts` table with status `pending_review`
4. Token usage logged to `aiAuditLog`

**Publishing Pipeline:**
1. Approved draft moved to `publishQueue` table with scheduled time
2. Background daemon (`src/daemon/index.ts`) checks queue every minute
3. When scheduled time reached, `runPublishQueue()` executes
4. Platform-specific publishing:
   - Substack: `publishToSubstack()` via substack-api
   - LinkedIn: `publishToLinkedIn()` via native fetch + ugcPosts API
5. Success: queue item marked published, draft status updated
6. Failure: retry logic with exponential backoff, max retries configurable
