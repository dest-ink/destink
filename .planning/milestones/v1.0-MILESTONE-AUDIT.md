### Integration Findings (Non-Blocking)

**1. publish-now is a stub (pre-existing)**
`POST /api/queue/[id]/publish-now` sets status to `publishing` but never calls the publisher. Items wait for `recoverStuckItems()` recovery (~15 min). Self-documented as "Tasks 7.1/7.2" scope. Affected: UI-05 (affordance exists, dispatch does not).

**2. Retry on permanently-failed items re-fails immediately (pre-existing)**
`POST /api/queue/[id]/retry` increments `retryCount` instead of resetting to 0. Items that exhausted 3 daemon retries will immediately re-fail. Fix: reset `retryCount` to 0 in the retry route. Affected: UI-05.

**3. DISABLE_INTERNAL_CRON documented but not implemented**
`docs/k3s-deployment.md` documents `DISABLE_INTERNAL_CRON` env var to prevent double-scheduling when daemon runs alongside Kubernetes CronJobs. `src/daemon/index.ts` does not check this var — `schedule()` always runs. Affected: DEPLOY-06 (guide accuracy).

**4. /api/research route uses inline errors, not apiError()**
10/11 API routes use `apiError()` from `src/lib/errors.ts`. The research route is fire-and-forget by design — HTTP response is always 200 with `{status: 'started'}`. Not a functional gap. Affected: UI-04 (consistency).
