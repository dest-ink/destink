### Integration Issues (Minor — Non-Blocking)

**1. publish-now is a stub**
`POST /api/queue/[id]/publish-now` sets status to `publishing` but never calls the publisher. Items wait for `recoverStuckItems()` recovery (~15 min). Self-documented as "Tasks 7.1/7.2" scope.

**2. Retry on permanently-failed items re-fails immediately**
`POST /api/queue/[id]/retry` increments `retryCount` instead of resetting to 0. Items that exhausted 3 daemon retries will immediately re-fail. Fix: reset `retryCount` to 0 in the retry route.

### Registry Structural Note

`Registry<T>.loadDirectory()` does not check `this.frozen` at entry — the dual-extension pattern (Phase 3.1) relies on this. If a frozen guard is ever added to `loadDirectory()`, the second extension scan will silently fail.
