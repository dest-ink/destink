Create the adapter registry singleton, mirroring the publisher-registry pattern from Plan 02:

1. Import `Registry` from `@/lib/providers/registry` and `ResearchAdapter`, `PROVIDER_API_VERSION` from `@/lib/providers/types`.

2. Create an `isResearchAdapter(val: unknown): val is ResearchAdapter` duck-type guard:
   - typeof val === 'object' && val !== null
   - id is string, name is string, displayName is string
   - search is function
   - apiVersion === PROVIDER_API_VERSION

3. Export `adapterRegistry` — a `new Registry<ResearchAdapter>(a => a.id)`.

4. Export `initAdapterRegistry(): Promise<void>` — calls `adapterRegistry.loadDirectory()` with:
   - dir: `path.resolve(process.cwd(), 'src/lib/research/adapters')`
   - suffix: `.adapter.ts` (also accept `.adapter.js` for production builds — same dual-suffix pattern as publisher-registry)
   - validate: `(mod) => isResearchAdapter(mod) ? mod : null`

This file mirrors src/lib/publishing/publisher-registry.ts in structure. Key difference: key extractor uses `a.id` instead of `p.platform`.
