  <name>Task 2: Deployment, Service, Job, CronJob, Ingress, and Secret templates</name>
  <files>deploy/helm/orbitl/templates/web-deployment.yaml, deploy/helm/orbitl/templates/web-service.yaml, deploy/helm/orbitl/templates/daemon-deployment.yaml, deploy/helm/orbitl/templates/migrate-job.yaml, deploy/helm/orbitl/templates/cronjob-publish.yaml, deploy/helm/orbitl/templates/cronjob-research.yaml, deploy/helm/orbitl/templates/cronjob-daily-summary.yaml, deploy/helm/orbitl/templates/ingress.yaml, deploy/helm/orbitl/templates/secret.yaml</files>
  <action>
Create all Kubernetes resource templates:

1. **secret.yaml**: Kubernetes Secret (type: Opaque) containing:
   - `DATABASE_URL`: use the `orbitl.databaseUrl` helper
   - All env vars from `values.env` (ANTHROPIC_API_KEY, ENCRYPTION_KEY, etc.)
   - Values base64-encoded using `b64enc` Helm function
   - Also include `NEXT_PUBLIC_APP_URL` and `AUTH_SECRET`

2. **web-deployment.yaml**: Deployment for the web service
   - Uses `web.image.repository:web.image.tag`
   - Replicas from `web.replicas`
   - containerPort: `web.port` (3021)
   - envFrom: secretRef to the chart's secret
   - env: PORT set to `web.port`, NODE_ENV=production
   - readinessProbe: httpGet path `/api/health`, port `web.port`, initialDelaySeconds: 10, periodSeconds: 5
   - livenessProbe: httpGet path `/api/health`, port `web.port`, initialDelaySeconds: 30, periodSeconds: 10
   - resources from `web.resources`

3. **web-service.yaml**: ClusterIP Service
   - Port 80 -> targetPort `web.port` (3021)
   - Selector using `orbitl.selectorLabels` plus `app.kubernetes.io/component: web`

4. **daemon-deployment.yaml**: Deployment for the daemon
   - Uses `daemon.image.repository:daemon.image.tag`
   - Replicas from `daemon.replicas` (should be 1 — daemon uses node-cron)
   - envFrom: secretRef to the chart's secret
   - No ports (daemon has no HTTP server)
   - No readiness/liveness probe (daemon is a process, not an HTTP service — rely on restart policy)
   - resources from `daemon.resources`
   - NOTE: When deploying to k8s with CronJobs enabled, the user should consider disabling node-cron in the daemon to avoid double-scheduling. This is a documentation concern for the k3s guide (Plan 04), not a code change.

5. **migrate-job.yaml**: Helm hook Job for database migrations
   - Annotations:
     - `"helm.sh/hook": pre-install,pre-upgrade`
     - `"helm.sh/hook-weight": "-5"`
     - `"helm.sh/hook-delete-policy": before-hook-creation,hook-succeeded`
   - Uses `web.image.repository:web.image.tag` (web image has drizzle-kit and migrations)
   - command: `["npx", "drizzle-kit", "migrate"]`
   - env: DATABASE_URL from secretKeyRef
   - restartPolicy: Never
   - backoffLimit: 3

6. **cronjob-publish.yaml**: CronJob (conditional on `cronJobs.publish.enabled`)
   - schedule from `cronJobs.publish.schedule`
   - concurrencyPolicy: Forbid
   - successfulJobsHistoryLimit: 3
   - failedJobsHistoryLimit: 1
   - Uses `jobs.image.repository:jobs.image.tag`
   - command: `["npx", "tsx", "src/jobs/publish.ts"]`
   - envFrom: secretRef
   - restartPolicy: OnFailure
   - resources from `jobs.resources`

7. **cronjob-research.yaml**: Same pattern as publish, using `cronJobs.research.schedule`, command `src/jobs/research.ts`

8. **cronjob-daily-summary.yaml**: Same pattern, using `cronJobs.dailySummary.schedule`, command `src/jobs/daily-summary.ts`

9. **ingress.yaml**: Conditional on `ingress.enabled`
   - Use `networking.k8s.io/v1` Ingress (standard, works with Traefik)
   - `ingressClassName: traefik` (default for k3s)
   - host from `ingress.host`
   - TLS section conditional on `ingress.tls` using `ingress.clusterIssuer` annotation for cert-manager
   - Backend: web service port 80

All templates MUST use the `orbitl.labels` and `orbitl.selectorLabels` helpers for labels/selectors. Add a `app.kubernetes.io/component` label (web, daemon, migrate, publish, research, daily-summary) to each resource.
