**Title:** "Deploying Orbitl to k3s"

**Assumed knowledge:** k3s is already running on a single node. The guide starts from `kubectl cluster-info` working. The user has `helm` installed.

**Sections:**

1. **Prerequisites**
   - k3s running (`kubectl cluster-info` returns success)
   - `helm` installed (v3+)
   - Docker installed (for building images)
   - A domain name pointing to the server's IP (for TLS)
   - API keys ready (Anthropic, Exa, Reddit, LinkedIn)

2. **Build and Load Images**
   - Build all three images locally:
     ```bash
     docker build -f docker/Dockerfile.web -t orbitl-web:0.1.0 .
     docker build -f docker/Dockerfile.daemon -t orbitl-daemon:0.1.0 .
     docker build -f docker/Dockerfile.jobs -t orbitl-jobs:0.1.0 .
     ```
   - Import into k3s (no registry needed for single-node):
     ```bash
     docker save orbitl-web:0.1.0 | sudo k3s ctr images import -
     docker save orbitl-daemon:0.1.0 | sudo k3s ctr images import -
     docker save orbitl-jobs:0.1.0 | sudo k3s ctr images import -
     ```
   - Note: For multi-node clusters, push to a container registry instead.

3. **Create Namespace**
   ```bash
   kubectl create namespace orbitl
   ```

4. **Configure Values**
   - Copy the default values and customize:
     ```bash
     cp deploy/helm/orbitl/values.yaml my-values.yaml
     ```
   - Edit `my-values.yaml`:
     - Set image tags to `0.1.0` (matching the build step)
     - Set `imagePullPolicy: Never` on all images (since loaded locally)
     - Set all env vars (ANTHROPIC_API_KEY, ENCRYPTION_KEY, etc.)
     - Set `ingress.enabled: true`, `ingress.host: your-domain.com`
     - Set `ingress.tls: true` (after cert-manager is configured)
     - Choose `postgresql.enabled: true` (bundled) or provide `externalDatabase.url`
   - IMPORTANT: Do NOT commit `my-values.yaml` to git — it contains secrets.

5. **Install with Helm**
   ```bash
   helm install orbitl deploy/helm/orbitl \
     --namespace orbitl \
     -f my-values.yaml
   ```
   - Explain what happens: Helm creates the Secret, runs the migration Job (hook), then creates Deployments, Service, CronJobs, and Ingress.

6. **Verify Deployment**
   ```bash
   kubectl -n orbitl get pods
   kubectl -n orbitl get jobs
   kubectl -n orbitl rollout status deployment/orbitl-web
   kubectl -n orbitl rollout status deployment/orbitl-daemon
   ```
   - Check migration completed: `kubectl -n orbitl get jobs` shows migrate job Completed
   - Check web is ready: `kubectl -n orbitl logs deployment/orbitl-web` shows Next.js started
   - Test health endpoint: `kubectl -n orbitl port-forward svc/orbitl-web 3021:80` then `curl http://localhost:3021/api/health`

7. **Configure TLS with cert-manager**
   - Install cert-manager:
     ```bash
     kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.17.2/cert-manager.yaml
     ```
   - Wait for cert-manager pods:
     ```bash
     kubectl -n cert-manager rollout status deployment/cert-manager
     ```
   - Create a ClusterIssuer for Let's Encrypt (provide the YAML inline):
     ```yaml
     apiVersion: cert-manager.io/v1
     kind: ClusterIssuer
     metadata:
       name: letsencrypt-prod
     spec:
       acme:
         server: https://acme-v02.api.letsencrypt.org/directory
         email: your-email@example.com
         privateKeySecretRef:
           name: letsencrypt-prod
         solvers:
           - http01:
               ingress:
                 class: traefik
     ```
   - Upgrade Helm release with TLS enabled:
     ```bash
     helm upgrade orbitl deploy/helm/orbitl \
       --namespace orbitl \
       -f my-values.yaml
     ```
     (with `ingress.tls: true` and `ingress.clusterIssuer: letsencrypt-prod` in my-values.yaml)
   - Verify certificate: `kubectl -n orbitl get certificate`

8. **Upgrading**
   - Rebuild images with new tag
   - Import into k3s
   - Update tag in `my-values.yaml`
   - `helm upgrade orbitl deploy/helm/orbitl -n orbitl -f my-values.yaml`
   - Helm automatically runs migration Job on upgrade

9. **Troubleshooting**
   - Migration Job fails: check logs with `kubectl -n orbitl logs job/orbitl-db-migrate`
   - Web pod not ready: check readiness probe logs, ensure HOSTNAME=0.0.0.0
   - CronJobs not running: `kubectl -n orbitl get cronjobs` to check schedule and last run
   - TLS not working: check cert-manager logs and ClusterIssuer status
   - Double-scheduling: If daemon's node-cron conflicts with k8s CronJobs, set `cronJobs.*.enabled: false` in values OR modify daemon to check an env var to disable its internal cron

**Style:** Practical, command-first. Each section shows the exact command, then explains what it does. Use fenced code blocks for all commands. Keep explanations brief — the user wants to deploy, not learn Kubernetes theory.

**Provider-agnostic:** Do not reference any specific cloud provider. Assume a VPS with a public IP. The only k3s-specific assumption is that Traefik is the default ingress controller (which it is for k3s).
