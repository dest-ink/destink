<task type="auto">
  <name>Task 1: Next.js standalone output, Dockerfiles, and health endpoint</name>
  <files>next.config.ts, docker/Dockerfile.web, docker/Dockerfile.daemon, src/app/api/health/route.ts</files>
  <action>
1. Add `output: 'standalone'` to `next.config.ts` inside the `nextConfig` object. Keep the existing webpack watchOptions config unchanged.

2. Rewrite `docker/Dockerfile.web` as a multi-stage standalone build:
   - Stage 1 (deps): node:22-alpine, copy package*.json, `npm ci`
   - Stage 2 (builder): node:22-alpine, copy package*.json, `npm ci`, copy all source, set `NEXT_TELEMETRY_DISABLED=1`, run `npm run build`
   - Stage 3 (runner): node:22-alpine, set `NODE_ENV=production`, `NEXT_TELEMETRY_DISABLED=1`, `PORT=3021`, `HOSTNAME=0.0.0.0`
   - Copy `--from=builder /app/.next/standalone ./` (the standalone server + minimal node_modules)
   - Copy `--from=builder /app/.next/static ./.next/static` (static assets not included in standalone)
   - Copy `--from=builder /app/public ./public` (public assets)
   - Copy `--from=builder /app/src/db ./src/db` (needed for drizzle-kit migrate in the migration service — this image is reused)
   - Copy `--from=builder /app/drizzle.config.ts ./` (needed for drizzle-kit migrate)
   - Copy `--from=builder /app/node_modules/drizzle-kit ./node_modules/drizzle-kit` and `--from=builder /app/node_modules/drizzle-orm ./node_modules/drizzle-orm` (migration dependencies — only needed when this image is used as the migrate service)
   - Add `HEALTHCHECK --interval=10s --timeout=5s --start-period=30s --retries=3 CMD wget -qO- http://localhost:3021/api/health || exit 1`
   - EXPOSE 3021
   - CMD `["node", "server.js"]`

   IMPORTANT: Do NOT use `npm start` — standalone output uses `node server.js` directly. Do NOT copy full `node_modules` — standalone includes only required modules.

   NOTE on migration dependencies: The research recommends reusing the web image for the migrate service. However, standalone output strips unused modules. If drizzle-kit dependencies are complex to cherry-pick, instead create a small separate Dockerfile stage or use `Dockerfile.jobs` (which has full npm ci) for the migrate service. Choose whichever approach is simpler — the key requirement is that the migrate service can run `npx drizzle-kit migrate`.

3. Update `docker/Dockerfile.daemon` minimally — it currently copies all source and runs tsx, which is fine for the daemon. No standalone needed here. Ensure it has:
   - `WORKDIR /app`
   - `COPY package*.json ./`
   - `RUN npm ci` (full install, not --omit=dev, because tsx is a dev dependency needed to run .ts files)
   - `COPY . .`
   - `CMD ["npx", "tsx", "src/daemon/index.ts"]`
   The only change needed: remove `--omit=dev` from npm ci since `tsx` is a devDependency.

4. Create `src/app/api/health/route.ts`:
   ```typescript
   import { NextResponse } from 'next/server';

   export function GET() {
     return NextResponse.json({ status: 'ok' });
   }
   ```
   This endpoint is NOT behind auth — it must be accessible without authentication for Docker/k8s health probes. Verify it is not caught by the auth middleware. Check `src/middleware.ts` to ensure `/api/health` is excluded from auth checks. If the middleware protects all `/api/**` routes, add `/api/health` to the exclusion list.
  </action>
