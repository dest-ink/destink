## Technical Notes

**Ordering guarantee:** In `src/jobs/publish.ts`, `await initRegistries()` is at line 10 (outside and before the try block), `await runPublishQueue()` is inside the try block at line 14. The initialization runs unconditionally before any publish dispatch can occur — if init throws, the call never reaches `runPublishQueue()`.

**Same ordering in research.ts:** `await initRegistries()` at line 11, `await runResearchForChannel()` inside the loop at line 29 — init always precedes dispatch.

**Dual-extension safety:** Publisher registry calls `loadDirectory()` with `.provider.ts` first, `.provider.js` second. Adapter registry does the same for `.adapter.ts` / `.adapter.js`. The `Registry.loadDirectory()` method writes via `Map.set()` (idempotent by key) and does not check the frozen flag internally — sequential calls are safe as confirmed in the phase research.

**Zero old-style calls remain:** `grep` on `initPublisherRegistry\|initAdapterRegistry` across daemon, jobs, and instrumentation returns zero matches — the migration to shared bootstrap is complete.
