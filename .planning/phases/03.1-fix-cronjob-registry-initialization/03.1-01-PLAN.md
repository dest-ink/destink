<objective>
Close the CronJob registry initialization gap: standalone job scripts (job:publish, job:research) currently call business logic without initializing the provider/adapter registries, causing silent failures. Additionally, registry auto-discovery only scans for .ts files, missing compiled .js files in production builds.

Purpose: Without this fix, CronJob-based publish runs fail with "No publisher registered for platform X" and research runs silently return empty results — both are deployment blockers.

Output: Shared bootstrap module, dual-extension registry discovery, wired job scripts and daemon.
</objective>

```typescript
import { initPublisherRegistry } from '@/lib/publishing/publisher-registry';
import { initAdapterRegistry } from '@/lib/research/adapter-registry';

/**
 * Initialize both provider registries (publishers + research adapters).
 * Call once at startup before any dispatch to publisherRegistry or adapterRegistry.
 * On failure, throws — a process without registries cannot function correctly.
 */
export async function initRegistries(): Promise<void> {
  await initPublisherRegistry();
  await initAdapterRegistry();
}
```

2. Update `src/lib/publishing/publisher-registry.ts` `initPublisherRegistry()` to call `loadDirectory()` twice — once with `.provider.ts` (dev/tsx) and once with `.provider.js` (production compiled). The existing first call is already present; add the second call immediately after it. The comment on the function already mentions .js support — update it to reflect that both are now active, not aspirational.

```typescript
export async function initPublisherRegistry(): Promise<void> {
  const providersDir = path.resolve(process.cwd(), 'src/lib/publishing/providers');
  await publisherRegistry.loadDirectory(
    providersDir,
    '.provider.ts',
    (mod) => (isPublisherProvider(mod) ? mod : null),
  );
  // Production builds compile .ts to .js — scan both extensions.
  // Registry.loadDirectory() does not check frozen flag internally,
  // so sequential calls are safe (Map.set is idempotent by key).
  await publisherRegistry.loadDirectory(
    providersDir,
    '.provider.js',
    (mod) => (isPublisherProvider(mod) ? mod : null),
  );
}
```

3. Update `src/lib/research/adapter-registry.ts` `initAdapterRegistry()` to call `loadDirectory()` twice — once with `.adapter.ts` and once with `.adapter.js`. Replace the aspirational comment about production builds with the actual second `loadDirectory()` call.

```typescript
export async function initAdapterRegistry(): Promise<void> {
  const adaptersDir = path.resolve(process.cwd(), 'src/lib/research/adapters');
  const validate = (mod: unknown): ResearchAdapter | null =>
    isResearchAdapter(mod) ? mod : null;

  // Development: tsx runs .ts source files directly
  await adapterRegistry.loadDirectory(adaptersDir, '.adapter.ts', validate);
  // Production: compiled .js output
  await adapterRegistry.loadDirectory(adaptersDir, '.adapter.js', validate);
}
```
